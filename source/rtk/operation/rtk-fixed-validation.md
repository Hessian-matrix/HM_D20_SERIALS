# RTK 状态与固定解验证

:::{admonition} 核心判断方法
:class: page-summary

普通用户无需查看设备内部差分链路状态。先确认**定位数据持续输出**，再在开阔环境确认进入 **RTK 固定解**；满足这两项即可判断当前差分通信链路正常。
:::

RTK 首次固定时间为 45 s。验证时应确保天空视野开阔，且差分源和通信链路正常。

## 验证顺序

1. **确认定位输出**：数据持续刷新，协议与出厂固件一致。
2. **选择查看工具**：NMEA 按{ref}`连接 NavStarTool <connect-navstartool>`查看；UBX 使用飞控地面站、遥控器、QGroundControl 或其他兼容设备查看。
3. **检查卫星状态**：将设备置于开阔环境，确认卫星数和定位数据持续更新。
4. **观察解状态**：确认进入 RTK 固定解，部分软件显示为 `Fixed`。
5. **确认稳定性**：固定解和位置输出没有频繁中断。

## 成功判据

:::{admonition} RTK 链路验证通过
:class: success-check

- 定位数据持续输出。
- 开阔环境下显示 **RTK 固定解**，且状态保持稳定。
:::

## 无法进入固定解时

| 现象 | 优先检查 |
| --- | --- |
| 无串口数据 | 供电、共地、TX/RX、波特率和固件输出 |
| 有数据但无定位 | GNSS 天线视野、遮挡和安装位置 |
| 4G 差分无效 | SIM 卡、网络覆盖、CORS 账号和 4G 天线 |
| LoRa 差分无效 | 基站供电、基站是否移动、两端天线和链路遮挡 |
| 可进入浮点解但固定解不稳定 | 天空视野、多路径、差分链路质量和现场干扰 |

详细处理流程见[故障排查](../troubleshooting/troubleshooting.md)。
