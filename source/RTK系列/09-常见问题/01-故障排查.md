# 故障排查

本页按可观察现象组织 HM-D20、HM-D13 和 HM-G51B 的常见问题。开始排查前，先记录完整产品型号、出厂固件、连接方式和所用差分链路，不要在信息不完整时同时修改多项配置。

## 无法上电或反复重启

:::{danger} D20误接线可能已经造成硬件损坏
D20只能使用5 V ±0.5 V供电。立即断电并核对[完整8-pin线束定义](../05-基本使用/D20接口与接线.md)：不得反接正负极，不得使用错误电压，不得将电源正极连接到TX、RX或其他信号线。纠正接线后仍无法上电时，请停止反复通电并联系技术支持。
:::

- D20/D13 供电应为 5 V ±0.5 V，并确认正负极连接正确。
- 检查电源、线缆和连接器是否松动或接触不良。
- 断开非必需外设后重新上电，排除外部接线短路或负载异常。
- 若由飞控或主控供电，确认其端口能够稳定供电；无法确认时使用独立合规电源测试。

## 串口不存在或没有数据

- D20/D13 的 UART IO 电平为 3.3 V，确认 USB 转 UART 模块或目标设备电平兼容。
- 确认 USB 转 UART 模块已被系统识别，可通过 `ls /dev/ttyUSB*` 查看。
- 确认波特率为 `115200`，TX/RX 已交叉连接，GND 已共地。
- 确认串口未被其他程序占用，当前用户具有串口访问权限。
- 确认当前固件与预期输出一致：D20地面版输出NMEA、无人机版输出UBX；D13仅地面版NMEA。

完整接线和串口检查见[设备连接与状态验证](../05-基本使用/index.rst)。

## 有串口数据但没有卫星定位

- 将设备移到天空视野开阔的位置，避开室内、金属遮挡、高楼和树木。
- 检查 GNSS 天线区域是否被平台结构或其他设备遮挡。
- 确认卫星数和信号强度是否持续更新。
- 保存原始串口数据，并记录测试地点、时间和安装方式。

## 4G版本无法获取差分数据

- 确认 SIM 卡已开通数据流量，设备所在位置具有蜂窝网络覆盖。
- HM-D20-4G 应确认外置 4G 天线已安装牢靠；HM-D13-4G 的 4G 天线内置。
- 使用 JR_NTRIP_Config_Tool_V1.2 检查服务器地址、端口、挂载点、用户名和密码。
- 确认 CORS/NTRIP 服务当前可用，账号未过期且挂载点正确。
- 在开阔环境重新上电，观察是否能够获得差分数据。

## LoRa基站与移动站无法连接

- 确认使用套件内的专用 D13 LoRa 基站硬件，基站和移动站为出厂配对组合。
- 确认基站和移动站均已上电，所需 LoRa 天线已正确安装。
- 同一局部场景只开启一个基站，不要同时运行多个基站。
- 减少基站和移动站之间的遮挡，并优先保持视距。
- 若设备或配套关系发生变化，记录全部产品型号和序列信息后联系技术支持，不要自行修改配对参数。

## 长时间停留在单点解或浮点解

- 确认移动站具有开阔天空视野，卫星数和信号质量正常。
- 4G版本检查 SIM、网络和 CORS/NTRIP 配置；LoRa版本检查基站供电、天线、遮挡和配套关系。
- 确认专用 D13 LoRa 基站已稳定架设，上电后没有被移动。
- 排除建筑、树木、金属结构和强电磁干扰造成的遮挡或多路径。

状态判断顺序见[RTK状态与固定解验证](../05-基本使用/RTK状态与Fixed验证.md)。

## 固定解频繁丢失或位置跳变

- 检查天空视野、卫星信号和现场多路径环境。
- 检查 4G/CORS 网络与账号，或 LoRa 基站供电、天线和现场遮挡是否发生变化。
- 检查电源和线缆是否稳定，天线连接是否松动。
- LoRa场景确认基站没有移动，基站与移动站之间无遮挡或弱遮挡。
- 保存异常前后的连续串口日志，避免只截取单帧数据。

## ArduPilot或PX4无法识别设备

- 确认 D20 使用无人机版固件并输出 UBX，默认波特率为 115200 bps。
- 确认飞控实际连接端口已配置为 GPS/UBX 输入。
- 确认飞控 UART 与 D20 的 3.3 V IO 电平兼容，TX/RX 已交叉连接并共地。
- 先确认飞控能够持续收到数据，再检查地面站中的 GPS 和 RTK 状态。
- 不要使用地面版 NMEA 固件代替无人机版 UBX 固件完成当前接入流程。

## Viobot2无法接收到RTK数据

- 先在 PC 上确认 D20 使用地面版固件，并有 NMEA 输出。
- 确认 RTK 驱动中的串口号与实际设备节点一致。
- 确认 D20 输出 GGA 和 RMC。
- 确认 Viobot2 上位机中已勾选 RTK 并重启设备。
- 通过 `rostopic echo /rtk_nmea` 确认驱动输出。
- 通过 `rostopic echo /baton/rtk` 确认 Viobot2 已解析 RTK 数据。

## 固件升级失败或升级后输出异常

- 确认升级过程中供电稳定，串口和数据线未断开。
- 确认选择的固件对应当前产品和目标输出：D20区分地面版NMEA与无人机版UBX，D13仅使用地面版NMEA。
- 升级完成后重新连接设备，检查卫星信息和输出协议；RTK 产品还应在开阔环境确认能否进入固定解。
- 若工具报错、设备无法启动或输出与预期不符，保留工具日志和固件信息，不要连续尝试不同固件。

具体流程见[固件升级](../08-参数配置和维护/02-固件升级.md)。

## G51B无法定位或没有输出

- 确认供电满足 4.0–5.5 V，极性和共地正确。
- 按交付接口资料确认 UART TX/RX、电平和默认 115200 bps 波特率。
- 确认主机能够接收 UBX-NAV-PVT 数据。
- 将天线布置在天空视野开阔的位置，避开金属遮挡和强干扰源。

## 联系技术支持前准备

请尽量同时提供以下信息，便于区分供电、接口、固件、差分链路和现场环境问题：

- 完整产品型号、硬件版本和固件版本。
- 供电方式、实测电压、UART连接方式和波特率。
- 4G/CORS 或 LoRa 套件组成与连接方式。
- 设备、天线、基站和现场环境照片。
- 连续原始串口日志，以及配置工具或地面站截图。
- 测试地点、时间、持续时长和问题复现步骤。
