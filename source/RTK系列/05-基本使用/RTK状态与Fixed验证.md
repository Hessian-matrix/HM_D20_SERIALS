# RTK 状态与固定解验证

RTK 首次使用的目标不是等待固定时长，而是确认定位输出、差分链路和解状态均有效。首次固定时间受天空视野、卫星分布、差分源、网络或 LoRa 链路、基站状态和现场环境影响。

## 验证顺序

1. **先确认串口输出**：定位数据持续刷新，协议与出厂固件一致。
2. **再确认卫星状态**：卫星数和信号强度持续更新，设备位于开阔环境。
3. **确认差分链路**：4G版本已连接CORS/NTRIP；LoRa版本的基站已上电且移动站链路正常。
4. **观察解状态**：状态从单点定位进入 RTK 浮点解，最终进入 RTK 固定解。部分软件界面分别显示为 `Float` 和 `Fixed`。
5. **确认稳定性**：设备保持运行，固定解状态和位置输出没有频繁中断。

## 成功判据

- 串口持续输出10 Hz NMEA或10 Hz UBX默认数据。
- 位置、卫星和信号信息有效。
- 差分链路没有持续报错或中断。
- 软件或目标设备显示 RTK 固定解。

## 无法进入固定解时

| 现象 | 优先检查 |
| --- | --- |
| 无串口数据 | 供电、共地、TX/RX、波特率和固件输出 |
| 有数据但无定位 | GNSS天线视野、遮挡和安装位置 |
| 4G差分无效 | SIM卡、网络覆盖、CORS账号和4G天线 |
| LoRa差分无效 | 基站供电、基站是否移动、两端天线和链路遮挡 |
| 可进入浮点解但固定解不稳定 | 天空视野、多路径、差分链路质量和现场干扰 |

详细处理流程见[故障排查](../09-常见问题/01-故障排查.md)。
