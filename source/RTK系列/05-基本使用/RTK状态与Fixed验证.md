# RTK 状态与固定解验证

普通用户无法直接查看设备内部的差分链路状态。RTK 首次使用时，应通过可观察的定位输出和解状态验证整条链路：定位数据持续输出，并在开阔环境进入 RTK 固定解，即可判断差分通信链路正常。RTK 首次固定的标准值为 45 s，实际过程仍会受到天空视野、卫星分布、差分源、网络或 LoRa 链路、基站状态和现场环境影响。

## 验证顺序

1. **先确认定位输出**：定位数据持续刷新，协议与出厂固件一致。
2. **再确认查看工具**：地面版 NMEA 使用 NavStarTool 查看；D20 无人机版 UBX 使用飞控地面站、遥控器或 QGroundControl 查看。
3. **检查卫星状态**：在对应工具中确认卫星数和定位数据持续更新，并将设备置于开阔环境。
4. **观察解状态**：最终进入 RTK 固定解。部分软件界面显示为 `Fixed`；最终以解状态为准。
5. **确认稳定性**：设备保持运行，固定解状态和位置输出没有频繁中断。

## 成功判据

- 定位数据持续输出，且协议与出厂固件一致。
- 对应工具中的卫星数和定位信息持续更新。
- 开阔环境下，软件或目标设备显示 RTK 固定解。

进入 RTK 固定解即表明当前差分通信链路正常；无需查找设备内部链路状态字段。

## 无法进入固定解时

| 现象 | 优先检查 |
| --- | --- |
| 无串口数据 | 供电、共地、TX/RX、波特率和固件输出 |
| 有数据但无定位 | GNSS天线视野、遮挡和安装位置 |
| 4G差分无效 | SIM卡、网络覆盖、CORS账号和4G天线 |
| LoRa差分无效 | 基站供电、基站是否移动、两端天线和链路遮挡 |
| 可进入浮点解但固定解不稳定 | 天空视野、多路径、差分链路质量和现场干扰 |

详细处理流程见[故障排查](../09-常见问题/01-故障排查.md)。
